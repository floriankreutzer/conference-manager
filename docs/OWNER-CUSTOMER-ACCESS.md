# Attributable owner customer access

The new default-off owner presentation adds an explicit path before the existing
Customer application. Platform access uses the existing Microsoft confirmation
queue. Customer and role selection does not establish identity or permissions;
the API independently checks designated owner receipts, actual current authority,
REAL target custody, the one-use proof and the final browser-bound confirmation.
The owner retains a separate attributable identity. No existing customer account
is adopted or impersonated, and an existing login requires explicit sign-out.

## Presentation ownership

Customer authentication owns the minimized confirmation, explicit account switch
and fixed same-origin form navigation. Platform production owns target selection,
paging and Microsoft approval. Both fixed clients reuse their existing private
protocol implementation; the actual shared operation queue stays pinned until
navigation or explicit status checking. Central DE/EN catalogs and existing
dialogs, focus handling, form controls, authentication frame and design tokens
remain in use. Owner modules are excluded from closed Demo authority graphs.

The signed hosted manifest includes ownerAccessEnabled. The paired API refuses
a mismatch with its immutable owner flag and refuses owner presentation without
Microsoft presentation. Build with the fixed PROTECTED_OWNER_CUSTOMER_ACCESS_ENABLED
input; the HTML marker only exposes a control and grants no server authority.
